35 · Agent-Loop & Harness

Erklär es einem 12-Jährigen Ein Agent ist wie ein Koch, der immer wieder zum Kühlschrank geht: Er überlegt, holt eine Zutat (ein Werkzeug-Ergebnis), überlegt neu, holt die nächste — bis das Gericht fertig ist. Das „immer wieder hingehen“ ist der Agent-Loop; die Küche, die ihm das ermöglicht, ist der Harness.

Intuition

Ein normales Chat-Modell antwortet einmal. Ein Agent tut das nicht — er läuft in einer Schleife: denken → Werkzeug aufrufen → Ergebnis anschauen → wieder denken. So kann er Dateien lesen, Code ausführen, im Web suchen und danach weitermachen. Der entscheidende Punkt: Es ist derselbe Loop, der sich wiederholt — nichts Magisches.

Der Harness ist das Rahmen-Programm um das Modell herum: Er baut den Prompt, ruft die API, führt Werkzeuge aus, verwaltet den Kontext und entscheidet, wann Schluss ist. Das Modell selbst ist nur „einen Schritt denken“. Gut zu wissen: Ein guter Agent braucht beides — ein gutes Modell UND einen guten Harness.

Was passiert technisch

while (modell will weitermachen) {
  1. senden:  Kontext + System-Prompt + verfügbare Werkzeuge
  2. inferenz: Modell antwortet (Text ODER ein Werkzeug-Aufruf)
  3. wenn Werkzeug-Aufruf:
       - führe das Werkzeug aus (z.B. read_file, bash, web_search)
       - hänge das Ergebnis an den Kontext an
       - springe zurück zu 1
  4. sonst:    fertig → gib die Antwort aus
}

Zwei Dinge, die Profis beachten:

  • Kontext wächst mit jedem Schritt. Jeder Loop-Schritt ist ein neuer API-Call, der die ganze bisherige Historie erneut sendet. Lange Agent-Runs werden dadurch teuer und langsam — das ist das O(n²)-Problem (siehe Konzept 36).
  • Der Harness muss abbrechen können. Ein hängender Agent (Rate-Limit, Endlos-Schleife, falsches Werkzeug) braucht einen sauberen Interrupt: Abbruch-Signal, Teil-Output behalten, keine doppelten Tool-Ausführungen.

Warum es mir (als Code-Nutzer) weiterhilft

  • Du verstehst, wo du steuerst: System-Prompt, Werkzeug-Liste, Kontext-Limit, Interrupt — all das gehört zum Harness, nicht zum Modell.
  • Du begreifst, warum „Modell gut“ allein nicht reicht — der Loop und die Kontext-Pflege entscheiden mit.
  • Du kannst Kosten abschätzen: Jeder Tool-Schritt = ein neuer Call = neue Tokens.
