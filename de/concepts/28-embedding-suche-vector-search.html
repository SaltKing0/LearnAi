28 · Embedding-Suche & Vector Search

Erklär es einem 12-Jährigen Stell dir du hast 1000 Bücher und suchst eines über "Dinosaurier". Du liest nicht alle — du gehts ins Schlagwortverzeichnis. Embedding-Suche ist wie ein magisches Verzeichnis: "Dinosaurier" ist nah bei "T-Rex" und "Saurier", aber weit weg bei "Pizza".

Was ist ein Embedding?

Ein Embedding ist ein Vektor (Liste von Zahlen) die einen Text repräsentiert. Ähnliche Texte haben ähnliche Vektoren.

"Katze" → [0.2, 0.8, 0.1, ...]
"Hund" → [0.3, 0.7, 0.2, ...]  // ähnlich
"Auto" → [0.9, 0.1, 0.8, ...]  // unterschiedlich

Cosine Similarity

Die Distanz zwischen zwei Vektoren misst man mit Cosine Similarity (Winkel zwischen den Vektoren). 1.0 = identisch, 0 = orthogonal, -1 = gegensätzlich.

Der RAG-Pipeline

  1. Chunking → Dokumente in Stücke teilen
  2. Embedding → Jedes Stück in Vektor umwandeln
  3. Storage → Vektoren in DB speichern
  4. Query → User-Frage auch embeddn
  5. Search → Ähnlichste Vektoren finden
  6. Generation → Top-K Ergebnisse in Prompt einfügen

Chunking-Strategien

  • Fixed Size → z.B. 500 Tokens pro Chunk
  • Recursive → Absätze → Sätze → Wörter
  • Semantic → Nach Bedeutungsgrenzen teilen
