09 · Agents / Tool-Use

Erklär es einem 12-Jährigen Normalerweise tippt das Modell nur Wörter. Ein Agent darf aber Werkzeuge benutzen — einen Taschenrechner, das Internet, Code. Es denkt: „Ich brauche das Ergebnis von 17×23“, ruft den Rechner auf, bekommt 391 zurück, und denkt dann weiter. So löst es Aufgaben, die nur Wörter allein nicht können.

Der Loop (das ist die ganze Magie)

wiederhole:
    antwort = modell(verlauf)
    wenn antwort ist ein Tool-Call:
        ergebnis = werkzeug.ausführen(antwort.argumente)
        verlauf += ergebnis
    sonst:
        return antwort   # fertig

Das Modell „ruft ein Werkzeug auf“ durch eine strukturierte Ausgabe (meist JSON: welches Tool + Argumente) — genau das Structured-Output-Pattern aus Konzept 07. Ein Framework (LangChain, etc.) ist im Kern nichts anderes als diese Schleife plus eine Sammlung vorgefertigter Werkzeuge.

Demo: der Agent-Loop (festes Szenario)

Animation eines Laufs: Frage → Modell will Rechner → Tool liefert 391 → Modell formuliert Antwort. Neustart alle paar Sekunden.

Bausteine eines Agents

  • Tools — Funktionen mit Beschreibung („Rechner: multipliziert zwei Zahlen“). Das Modell wählt anhand der Beschreibung.
  • Stop-Bedingung — wann ist die Aufgabe gelöst? (kein Tool-Call mehr, oder max. Schritte).
  • Planung — bei komplexen Tasks plant das Modell Zwischenschritte (verwandt mit CoT, 07).
  • Memory — was im Verlauf bleibt, was vergessen wird.

Warum das für dich als Code-Nutzer zentral ist

  • Automatisierung: API aufrufen, Dateien lesen/schreiben, Code ausführen — das Modell orchestriert.
  • Eigene Tools: du schreibst eine Funktion + Beschreibung, das Modell nutzt sie.
  • Kosten/Latenz: jeder Schritt = ein Modell-Aufruf → Loops können teuer/lang werden.
  • Sicherheit: Tool-Aufrufe ausführen = Code ausführen → Sandboxing nötig.
