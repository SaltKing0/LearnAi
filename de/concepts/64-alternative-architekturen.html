64 · Alternative Architekturen

Erklär es einem 12-Jährigen Der Transformer ist wie ein Schüler, der bei jedem neuen Satz das ganze Buch noch einmal von vorn liest. Das ist gründlich, aber umso langsamer, je dicker das Buch wird. Alternative Architekturen sind Schüler, die stattdessen ein kleines Notizbuch (einen „Zustand“) führen und es beim Lesen aktualisieren — jedes neue Wort verändert nur das Notizbuch. Das Buch kann riesig sein, das Notizbuch bleibt gleich groß, also wird das Lesen nie langsamer. Der Preis: Sie übersehen vielleicht ein Detail, das das komplette Wiederlesen gefunden hätte.

Intuition

Attention ist die Superkraft des Transformers: Jedes Token kann auf jedes frühere Token schauen. Doch diese Kraft hat ihren Preis. Bei einer Folge aus n Tokens muss sich ein Token an Position n mit allen n vorherigen vergleichen — der Aufwand wächst mit n × n = O(n²). Verdoppelt man den Kontext, wird der Attention-Aufwand viermal so groß. Der KV-Cache (Konzept 57) hilft beim Inferenz-Zeitpunkt, aber das quadratische Prefill und der wachsende Cache begrenzen weiterhin, wie lange ein Kontext ein Transformer günstig verarbeiten kann.

Alternative Architekturen behalten die Idee „sage das nächste Token voraus“, ersetzen aber die Schau-auf-alles-Attention durch einen komprimierten Zustand fester Größe, der Schritt für Schritt aktualisiert wird. Jedes neue Token leistet dabei einen konstanten Aufwand, sodass die Kosten linear (O(n)) mit der Sequenzlänge wachsen statt quadratisch. Das ermöglicht sehr lange Kontexte und günstigere Edge-/On-Device-Inferenz — auf Kosten von teils etwas geringerer Qualität oder schwierigerem Training.

Was passiert technisch

  • Quadratischer Engpass. Volle Self-Attention baut eine n×n-Attention-Matrix auf: Jedes Token bewertet sich gegen jedes andere. Speicher und Rechenaufwand skalieren beide mit O(n²) — deshalb ist das „volle Kontextfenster“ teuer (siehe Konzept 57).
  • State-Space-Modelle (SSM / Mamba). Ein verborgener Zustand h (ein Vektor fester Größe) wird bei jedem Schritt aktualisiert: h_t = A·h_{t-1} + B·x_t, und die Ausgabe wird aus h_t gelesen. Da der Zustand eine feste Größe hat, ist jeder Schritt O(1) und die ganze Sequenz O(n). Mamba ergänzt ein datenabhängiges Gating/Selektions- Mechanismus, sodass das Modell selbst entscheiden kann, was es behält und was es vergisst — wie eine schlauere, gelernte Rekurrenz. Ein schneller „selective scan“ macht das Training parallel genug, um praktisch zu sein.
  • RWKV. Verbindet einen rekurrenten linearen Zustand im RNN-Stil mit einem transformerartigen Trainingsablauf. Es nutzt eine rekurrente Form von Attention (einen „wKV“-Mechanismus), sodass die Inferenz O(1) pro Token ist — kein KV-Cache, der mit dem Kontext wächst — und sich trotzdem wie ein Transformer trainieren lässt. Oft zusammengefasst als „RNN bei der Inferenz, Transformer beim Training.“
  • Hybride. Viele neuere Modelle behalten ein paar volle Attention-Schichten (für die Teile, in denen globaler Kontext wirklich zählt) und ersetzen den Rest durch lineare/SSM-Schichten. So bekommt man den Großteil des Langkontext-Vorteils mit weniger Qualitätsverlust, als wenn man komplett auf einen Zustand setzt.

Warum es mir (als Code-Nutzer) weiterhilft

  • Wenn ich „Mamba“ oder „RWKV“ in einem Modellnamen oder Paper sehe, weiß ich: Es zielt auf Langkontext- und Niedrig-Latenz-Anwendungsfälle — nicht auf eine grundlegend andere Art von KI.
  • Für sehr lange Dokumente oder Streams (Logs, Codebasen, ganze Bücher) können zustandsbasierte Modelle pro Token deutlich günstiger sein als ein Transformer bei gleicher Kontextlänge.
  • On-Device-/Edge-Inferenz profitiert: Ein Zustand fester Größe bedeutet, dass der Speicher flach bleibt, während der Prompt wächst — anders als beim Transformer, dessen KV-Cache aufbläht (vgl. Konzept 57).
  • Der Kompromiss ist für mich als Nutzer wichtig: Wenn meine Aufgabe präzises Abrufen eines Details in einem riesigen Kontext braucht, ist ein Transformer oder Hybrid oft sicherer; wenn ich einen riesigen Stream schnell und günstig verarbeiten muss, glänzt ein Zustandsmodell.
