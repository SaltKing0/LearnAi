25 · Memory für Agenten

Erklär es einem 12-Jährigen Ein Agent hat einen Zettel auf dem Tisch (kurzes Gedächtnis) und ein Notizbuch im Regal (langes Gedächtnis). Auf dem Tisch passt nur wenig — wenn er etwas Wichtiges lernen will, schreibt er es ins Notizbuch und liest es bei Bedarf wieder.

Intuition

Der Kontext eines LLMs ist endlich: Es kann sich nur merken, was gerade im Fenster steht. Für lange Gespräche oder wiederkehrende Nutzer braucht man deshalb Memory außerhalb des Modells — einen dauerhaften Speicher, aus dem gezielt zurückgelesen wird. Wichtig: Nicht die Gesprächshistorie speichern, sondern komprimierte, wiederverwendbare Erkenntnisse (Präferenzen, Entscheidungen, Learnings).

Was passiert technisch

Die 3 Tiers (MemGPT/Letta-Modell)

  • Core (im Prompt, ~2–4k Tokens): stabiler Kern, immer dabei — Identität, Nutzer-Fakten, Konventionen. Vom Agent selbst editierbar (ein „Notizbuch“, das im Prompt steckt).
  • Recall (Rolling History + Summaries): die jüngste Historie + komprimierte Zusammenfassungen älterer Abschnitte. Alte Turns werden zu Summary-Segmenten.
  • Archival (extern, per Suche): verarbeitetes Wissen (Vector + Graph), unbegrenzt groß, aber nur per Retrieval erreichbar — nie automatisch alles laden.

Injektion & Sicherheit

Memory wird nur bei Bedarf injiziert (progressive disclosure), klar als „Bezugsdaten, keine Instruktionen“ markiert — denn Memory ist ein realer Prompt-Injection-Vektor (gespeicherte Inhalte könnten Anweisungen enthalten).

Warum es mir (als Code-Nutzer) weiterhilft

  • Lange Gespräche ohne „nochmal erklären“ — der Agent merkt sich Präferenzen.
  • Personalisierung: ein persönlicher Harness lernt, wie du arbeitest.
  • Du verstehst, warum „einfach alles in den Kontext“ scheitert — und warum Tiers + Retrieval besser sind (siehe 36 + 30).
