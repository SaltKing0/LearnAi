55 · Software-Engineering & Lebenszyklus

Erklär es einem 12-Jährigen Code schreiben ist der spaßige Teil, aber ein echtes Projekt ist ein Teamsport mit Regeln. Du planst in kurzen Runden (Agile), speicherst jede Version, um zurückgehen zu können (Git), lässt Teamkollegen deine Arbeit vor dem Merge prüfen (Code Review) und testest, damit du nichts kaputt machst, was schon lief. Diese Seite handelt vom Prozess rund um den Code.

Intuition

Software verbringt den Großteil ihres Lebens damit, geändert zu werden, nicht geschrieben. Deshalb ist die entscheidende Disziplin, Änderungen sicher und umkehrbar zu machen: kleine Schritte, Versionskontrolle, automatisierte Tests und Review. Das gilt egal ob CRUD-App oder KI-Agent-Harness — die Praktiken sind dieselben.

Versionskontrolle & Zusammenarbeit

  • Git: Schnappschüsse (Commits) deines ganzen Projekts; Branch = eine getrennte Arbeitslinie; Merge = Linien kombinieren.
  • Branching-Strategien: Gitflow (langlebige develop- + Feature/Release/Hotfix-Branches — gut für Releases); Trunk-based (alle committen in kleinen PRs auf main, Feature-Flags — gut für CI/CD-Tempo).
  • Code Review + Pull Requests: die Änderung lebt auf einem Branch, ein Mensch (oder eine KI) prüft den Diff, CI läuft Checks, dann wird gemerged. Review ist ein Qualitäts-Gate und ein Wissens-Teiler.

Automatisierte Test-Frameworks (Jest, pytest, Playwright usw.) führen diese bei jeder Änderung aus, meist in CI. Für KI erweitert sich „Testen" um Evals und LLM-as-Judge — siehe 34.

Warum hilft mir das (als KI-/Code-Nutzer)

  • Eval-getriebene Entwicklung: Modellverhalten wie Tests behandeln (zuerst die erwartete Antwort schreiben) ist TDD auf KI angewendet (34).
  • Agent-Harnesses sind Software: sie brauchen Versionskontrolle, Review und Tests wie alles andere — die „Agent-Schleife" ist nur Code.
  • PR-Workflow: die Git/Review/CI-Schleife ist genau, wie du an echten KI-Projekten zusammenarbeitest.
  • Prompt als Code: Prompts, Configs und Evals gehören in die Versionskontrolle, reviewt wie Code.
