09 · Sicherheit & Compliance

Erklär es einem 12-Jährigen Sicherheit heißt die Türen abschließen: nur die Richtigen reinlassen (Authentifizierung), nur tun, was sie dürfen (Autorisierung), und dass Nachrichten unterwegs nicht gelesen oder gefälscht werden können (Verschlüsselung). Bei KI gibt es eine Extra-Tür im Auge zu behalten — das Modell selbst kann dazu getrickst werden, Dinge zu tun, die es nicht soll (Prompt Injection).

Intuition

Sicherheit ist ein Threat Model: Du fragst „wer könnte das angreifen und wie?" und designst dann Verteidigung. Für eine normale Web-App sind die großen Risiken Injection, kaputte Zugriffskontrolle und Datenlecks. Für eine KI-App kommen Prompt Injection und Daten-Exposition durch das Modell dazu. Compliance (DSGVO, SOC 2 usw.) ist die rechtliche/Prüf-Seite — nachweisen, dass du verantwortungsvoll mit Daten umgehst.

Anwendungssicherheit (AppSec)

OWASP Top 10 ist die Standardliste der Web-App-Risiken. Die, die du am häufigsten triffst:

Regel: traue Eingaben nie. Sanitiere/validiere alles, was eine Vertrauensgrenze überschreitet.

Authentifizierung & Autorisierung

  • Authentifizierung (wer bist du?) vs. Autorisierung (was darfst du?).
  • OAuth 2.0: delegierte Autorisierung — lässt eine App auf deine Daten zugreifen, ohne dein Passwort (z. B. „Mit Google anmelden").
  • OpenID Connect (OIDC): Identitäts-Ebene über OAuth 2.0 — liefert das Wer.
  • JWT: signiertes Token mit Claims (wer + was er darf) — zustandslose Auth, aber sorgfältig validieren (Signatur, Ablauf, Audience).
  • RBAC / ABAC: Rollenbasierte (Berechtigungen pro Rolle) vs. Attributbasierte (Berechtigungen pro Attributen/Kontext) Zugriffskontrolle.

Kryptografie

  • Verschlüsselung at rest (gespeicherte Daten — AES) und in transit (bewegte Daten — TLS/HTTPS).
  • Hashing: Einweg (Passwörter, Integrität) — SHA-256; Passwörter nie im Klartext, sondern gesalzen (bcrypt/argon2).
  • PKI / Zertifikate: Public-Key-Infrastruktur — wie TLS über Zertifizierungsstellen Vertrauen herstellt (das ist das „Schloss" im Browser).
  • Key-Management: Schlüssel sind die Kronjuwelen — nutze einen Key Vault (AWS KMS usw.), rotiere sie, hartcode nie Secrets.

Warum hilft mir das (als KI-/Code-Nutzer)

  • Prompt Injection ist das AppSec der LLMs — nicht vertrauenswürdige Eingabe lenkt das Modell (26).
  • API-Keys & Secrets: nie Keys in Code ausliefern; env vars / Vaults — dieselbe Key-Management-Disziplin (12).
  • Sandboxing: modellgenerierten Code oder Tools auszuführen braucht Isolation (40).
  • Datenschutz: was du an ein Modell schickst, kann deinen Kontrollbereich verlassen — eine Compliance-Entscheidung (14).
