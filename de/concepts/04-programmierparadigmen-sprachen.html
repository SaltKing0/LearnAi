04 · Programmierparadigmen & Sprachen

Erklär es einem 12-Jährigen Ein Paradigma ist eine Denkweise beim Schreiben von Code. Objektorientiert ist wie eine Schule organisieren: Schüler und Klassen. Funktional ist wie ein Rezept, das aus denselben Zutaten immer dasselbe Gericht ergibt — keine heimlichen Änderungen. Und eine Sprache ist nur ein Dialekt, der eine Denkweise leicht und eine andere schwer macht.

Intuition

Sprachen unterscheiden sich weniger darin, „was sie können" (alle sind Turing-vollständig), sondern mehr darin, welches Paradigma sie natürlich machen und wie sie deinen Code in etwas verwandeln, das die Maschine ausführt. Die Paradigmen zu kennen hilft, jede Codebasis zu lesen und das richtige Werkzeug zu wählen — auch im KI-Ökosystem, das ein Mix aus Python (imperativ/OOP), TypeScript (OOP + FP) und Rust/Go (Systeme + Concurrency) ist.

Die Paradigmen

ParadigmaKernideeBild im KopfTypische Sprachen
ImperativSag wie: Schritt-für-Schritt-BefehleEin Rezept mit nummerierten SchrittenC, Python, JS
DeklarativSag was du willst, nicht wie„Gib mir alle Nutzer über 18" (SQL)SQL, HTML, CSS, YAML
ProzeduralImperativ + wiederverwendbare FunktionenRezept, Schritte als benannte HelferC, frühes Python
ObjektorientiertDaten + Verhalten in Objekten mit Zustand bündelnSchule: Schüler, Klassen, MethodenJava, C#, Python, TS
FunktionalPure Funktionen, kein geteilter veränderlicher ZustandRezept: gleiche Eingabe → gleiche Ausgabe, immerHaskell, Clojure, F#, viel JS/TS

Echter Code ist fast immer multi-paradigmatisch — Python und TypeScript mischen OOP und FP frei. Das „Paradigma" ist ein Stil, den du pro Problem wählst, kein Käfig.

Sprachfamilien — wie Code zu Maschinencode wird

FamilieWie es läuftTrade-offBeispiele
Kompiliert (nativ)Compiler → Maschinencode, läuft direktSchnell, aber Compile-Schritt + Speicher (oder nicht)C, C++, Rust, Go
Interpretiert / SkriptInterpreter führt Quellcode Zeile für Zeile ausSchnell geschrieben, langsamer, braucht RuntimePython, JavaScript, Ruby
Verwaltet / VM-basiertKommt zu Bytecode, läuft auf VM mit GCPortabel + sicher (GC), etwas OverheadJava, C#, Kotlin
  • Kompiliert: C++/Rust für performance-kritische Inferenz; Go für schnelle, einfache nebenläufige Dienste (super für Agent-Backends).
  • Interpretiert: Python ist die KI-Lingua-Franca (PyTorch, transformers); JavaScript/TypeScript treibt das Web + die meisten Agent-Frameworks.
  • Verwaltet: Java/C# in großen Enterprise-Stacks (Spring Boot, ASP.NET).

Warum hilft mir das (als KI-/Code-Nutzer)

  • Werkzeuge wählen: Python für Modellarbeit, TypeScript für Browser/Agent-UIs, Rust/Go für High-Throughput-Serving — jedes ist das richtige Paradigma für seinen Job.
  • Modellcode lesen: PyTorch ist OOP mit funktionalem Einschlag; das zu erkennen macht Transformer-Code lesbar.
  • Funktionales Denken in Agents: Tool-Calls als pure Funktionen (Eingabe → Ausgabe) macht Agent-Schleifen testbar und vorhersagbar.
  • Deklarative Skills: Prompts, YAML-Configs und SQL sind deklarativ — du beschreibst das Ergebnis, die Engine findet heraus wie.
