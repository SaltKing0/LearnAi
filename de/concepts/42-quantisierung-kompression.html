42 · Quantisierung & Kompression

Erklär es einem 12-Jährigen Stell dir ein Bild im Super-HD (4K) — sieht fantastisch aus, aber braucht eine ganze Festplatte. Quantisierung ist wie das Bild auf Full HD verkleinern: Du verlierst ein bisschen Qualität, aber es auf jedem Tablet läuft. Bei Modellen bedeutet das: weniger Speicher, weniger Rechenpower, minimal weniger Intelligenz.

Warum Quantisierung?

Ein 70B-Modell braucht ~140GB RAM im FP16-Format. Kein Normalo hat das. Quantisierung reduziert das auf ~35GB (Q4) oder sogar ~20GB (Q2) — und plötzlich läuft es auf einer Gaming-GPU.

Quantisierungs-Levels

FormatBitsGröße (70B)QualitätUse-Case
FP1616~140 GB100%Server, A100
Q88~70 GB~99%High-End GPU
Q55~44 GB~97%RTX 4090
Q44~35 GB~95%Gaming GPU
Q22~18 GB~90%Laptop, Edge

Quantisierungs-Methoden

  • PTQ (Post-Training Quantization) → Modell nach dem Training komprimieren. Einfach, aber Qualitätsverlust.
  • QAT (Quantization-Aware Training) → Modell lernt während des Trainings die Kompression. Besser, aber teuer.
  • GPTQ → Meta's Methode, Layer für Layer quantisieren mit Optimal Brain Surgeon.
  • AWQ (Activation-Aware Weight Quantization) → wichtige Gewichte weniger komprimieren als unwichtige.
  • GGUF/GGML → Format für llama.cpp, auf CPU lauffähig.

Pragische Faustregeln

  • GPU > 24GB → FP16 oder Q8
  • GPU 12-24GB → Q5 oder Q4
  • GPU < 12GB → Q4 oder Q3
  • Nur CPU → Q4/Q2 GGUF
