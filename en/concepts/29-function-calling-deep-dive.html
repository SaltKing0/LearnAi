29 · Function Calling (Deep Dive)

Explain it to a 12-year-old Imagine you're in a restaurant. You tell the waiter "I'd like the menu". The waiter brings it to you. Function calling is like that waiter — the model says "I need this now" and the tool delivers it.

The loop in detail

  1. User asks: "What's the weather in Berlin?"
  2. The model recognizes: "I need weather data" → emits a function call
  3. Your code runs the tool: get_weather("Berlin")
  4. The result is returned to the model
  5. The model formulates the answer: "In Berlin it's 18°C and sunny"

Tool definition (OpenAI format)

{
  "name": "get_weather",
  "description": "Get current weather for a city",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "The city name"
      }
    },
    "required": ["city"]
  }
}

Multi-tool calls

The model can call several tools at once:

// model returns two calls:
[
  { "name": "get_weather", "args": { "city": "Berlin" } },
  { "name": "get_weather", "args": { "city": "Munich" } }
]

Error handling

What if the tool fails?

  • Retry → the model tries again with different parameters
  • Fallback → suggest alternative tools
  • Ask the user → "I couldn't find that, did you mean...?"

Streaming with function calls

With streaming, the calls arrive piece by piece. Your code must do "function call accumulation" — collect the parts and only execute once everything is there.
