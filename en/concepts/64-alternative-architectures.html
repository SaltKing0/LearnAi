64 · Alternative Architectures

Explain it to a 12-year-old The Transformer is like a student who, for every new sentence, re-reads the whole book from the start. That's thorough but slow the longer the book gets. Alternative architectures are students who instead keep a small notebook (a "state") and update it as they read — each new word only updates the notebook. The book can be huge, but the notebook stays the same size, so reading never slows down. The trade-off: they might miss a detail that re-reading everything would have caught.

Intuition

Attention is the Transformer's superpower: every token can look at every past token. But that power has a price. For a sequence of n tokens, a token at position n must compare against all n previous tokens — the work grows as n × n = O(n²). Doubling the context makes the attention cost four times larger. The KV-cache (Concept 57) helps at inference time, but the quadratic prefill and the growing cache still bound how long a context a transformer can handle cheaply.

Alternative architectures keep the "predict the next token" idea but replace the look-at-everything attention with a compressed, fixed-size state that is updated step by step. Each new token does a constant amount of work, so cost grows linearly (O(n)) with the sequence length instead of quadratically. That unlocks very long contexts and cheaper edge/on-device inference — at the price of sometimes slightly lower quality or harder training.

What happens technically

  • Quadratic bottleneck. Full self-attention builds an n×n attention matrix: every token scores itself against every other token. Memory and compute both scale O(n²), which is why "full context window" is expensive (see Concept 57).
  • State-space models (SSM / Mamba). A hidden state h (a fixed-size vector) is updated at every step: h_t = A·h_{t-1} + B·x_t, and the output is read from h_t. Because the state is constant size, each step is O(1) and the whole sequence is O(n). Mamba adds a data-dependent gating/selection mechanism so the model can decide what to keep vs. forget — like a smarter, learned recurrence. A fast "selective scan" makes training parallel enough to be practical.
  • RWKV. Blends the RNN-style linear state with a transformer-like training loop. It uses a recurrent form of attention (a "wKV" mechanism) so inference is O(1) per token — no KV-cache that grows with context — while still being trainable like a transformer. Often summarized as "RNN at inference, transformer at training."
  • Hybrids. Many recent models keep a few full-attention layers (for the parts where global context really matters) and replace the rest with linear/SSM layers. This gets most of the long-context benefit with less quality loss than going all-in on a state.

Why this helps me (as a code user)

  • When I see "Mamba" or "RWKV" in a model name or a paper, I know it targets long-context and low-latency use cases — not that it's a fundamentally different kind of AI.
  • For very long documents or streams (logs, codebases, whole books), state-based models can be dramatically cheaper per token than a transformer at the same context length.
  • On-device / edge inference benefits: a constant-size state means memory stays flat as the prompt grows, unlike a transformer whose KV-cache balloons (compare Concept 57).
  • The trade-off matters for me as a user: if my task needs precise recall of one detail buried in a huge context, a transformer or hybrid is often safer; if it needs to process a massive stream fast and cheap, a state model shines.
