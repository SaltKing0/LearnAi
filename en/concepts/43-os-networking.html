43 · Operating Systems & Networking

Explain it to a 12-year-old The operating system is the manager of your computer: it decides which program gets the CPU, hands out memory, and lets many programs run "at the same time." Networking is the postal system between computers — it wraps your message in envelopes (TCP/IP), looks up the address (DNS), and delivers it over HTTP. Almost everything you do online is one program mailing another.

Intuition

Two layers sit under every app you write: the OS (processes, threads, memory) and the network (how machines talk). You don't often touch them directly, but they decide your program's speed, reliability, and failure modes — a slow API call, a deadlock, or an out-of-memory crash all come from here.

Threading, concurrency & memory

  • Process vs. thread: a process is a running program with its own memory; threads are lighter workers inside one process sharing its memory.
  • Concurrency = making progress on many things at once (interleaving). Parallelism = actually running them on multiple cores at once.
  • Race condition: two threads write the same memory without coordination → unpredictable results. Fixed with locks, atomic ops, or message passing.
  • Deadlock: two threads each wait for a resource the other holds → both freeze forever.
  • Memory management: the OS hands out memory in pages; your language handles the rest — manual (C), reference-counted/GC (Python, Java, Go), or ownership-based (Rust, catching errors at compile time).

Networking — the stack

flowchart TB APP["Application: HTTP/HTTPS, DNS, WebSockets"] --> TCP["Transport: TCP (reliable) / UDP (fast)"] TCP --> IP["Internet: IP — addressing & routing"] IP --> LINK["Link: Ethernet / Wi-Fi — physical frames"]

The TCP/IP stack — each layer wraps the one below it. HTTPS adds encryption at the application layer.

  • TCP is reliable: it retransmits lost packets and orders them (used by HTTP). UDP is fast but lossy (used by video calls, games).
  • HTTP/HTTPS: request/response over TCP; HTTPS = HTTP inside a TLS-encrypted tunnel. Methods: GET, POST, PUT, DELETE. Status codes: 2xx ok, 3xx redirect, 4xx client error, 5xx server error.
  • DNS: the phone book — turns example.com into an IP address (a distributed lookup, with caching at every hop).
  • Sockets: the API your program uses to open a connection and send/receive bytes; the OS manages the actual packets.

Why this helps me (as an AI/code user)

  • API calls & latency: every LLM request is a network round-trip; retries, timeouts, and streaming (WebSockets/SSE) are networking concepts (12).
  • Parallel tool calls in agents: running several tool calls concurrently is a concurrency problem — where threads/async and shared state bite (35, 39).
  • Streaming: token-by-token output arrives over a persistent connection; understanding HTTP/SSE/WebSockets demystifies it.
  • Debugging: "5xx" vs. "4xx", timeouts, and DNS failures are the everyday vocabulary of production AI apps.
