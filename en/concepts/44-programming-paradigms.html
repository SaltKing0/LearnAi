44 · Programming Paradigms & Languages

Explain it to a 12-year-old A paradigm is a way of thinking when you write code. Object-Oriented is like organizing a school by students and classes. Functional is like a recipe that always gives the same dish from the same ingredients — no sneaky changes. And a language is just a dialect that makes one way of thinking easy and another hard.

Intuition

Languages differ less in "what they can do" (all are Turing-complete) and more in which paradigm they make natural and how they turn your code into something the machine runs. Knowing the paradigms helps you read any codebase and pick the right tool — including in the AI ecosystem, which is a mix of Python (imperative/OOP), TypeScript (OOP + FP), and Rust/Go (systems + concurrency).

The paradigms

ParadigmCore ideaMental imageTypical languages
ImperativeSay how: step-by-step commandsA recipe with numbered stepsC, Python, JS
DeclarativeSay what you want, not how"Give me all users over 18" (SQL)SQL, HTML, CSS, YAML
ProceduralImperative + reusable functions/proceduresRecipe, but steps as named helpersC, early Python
Object-OrientedBundle data + behavior into objects with stateSchool: students, classes, methodsJava, C#, Python, TS
FunctionalPure functions, no shared mutable stateRecipe: same in → same out, alwaysHaskell, Clojure, F#, much of JS/TS

Real code is almost always multi-paradigm — Python and TypeScript let you mix OOP and FP freely. The "paradigm" is a style you choose per problem, not a cage.

Language families — how code becomes machine code

FamilyHow it runsTrade-offExamples
Compiled (native)Compiler → machine code, runs directlyFast, but compile step + manual memory (or not)C, C++, Rust, Go
Interpreted / scriptingInterpreter runs source line by lineFast to write, slower to run, needs runtimePython, JavaScript, Ruby
Managed / VM-basedCompiles to bytecode, runs on a virtual machine with GCPortable + safe (GC), some overheadJava, C#, Kotlin
  • Compiled: C++/Rust for performance-critical inference; Go for fast, simple concurrent services (great for agent backends).
  • Interpreted: Python is the AI lingua franca (PyTorch, transformers); JavaScript/TypeScript powers the web + most agent frameworks.
  • Managed: Java/C# in big enterprise stacks (Spring Boot, ASP.NET).

Why this helps me (as an AI/code user)

  • Choosing tools: Python for model work, TypeScript for browser/agent UIs, Rust/Go for high-throughput serving — each is the right paradigm for its job.
  • Reading model code: PyTorch is OOP with a functional flavor; recognizing that makes transformers code readable.
  • Functional thinking in agents: treating tool calls as pure functions (input → output) makes agent loops testable and predictable.
  • Declarative skills: prompts, YAML configs, and SQL are declarative — you describe the outcome, the engine figures out how.
