40 · Deployment

Explain it to a 12-year-old A model on your desk is useless to anyone. "Deployment" means: setting it up so others can use it — as a service on the internet, or even on a phone. And "quantization" is the diet: shrinking the model so it runs on weaker hardware.

Three ways to deploy a model

  • API / cloud (inference server) — you start e.g. vLLM/ Ollama and call it like in Concept 12, just self-hosted (from 06/14). Scales, but needs a server/GPU.
  • Edge / local — the model runs on your own machine/ phone/in the browser (WebGPU, llama.cpp). Private, offline, but limited power.
  • Embedded / on-premise — in your company, no data leaves the house (14).

Three deployment paths; quantization is what makes edge/on-premise possible in the first place.

Quantization (connection to 04/17)

Models store weights as 16-bit floats. Quantization reduces them to 8/4 bits — the model becomes ~4× smaller and faster, often with barely visible quality loss (04). That's why a 7B model suddenly runs on a laptop. Less RAM, less latency (17), no GPU needed.

Why this is central for you as a code user

  • Self-hosting (14): your own API without third parties, control.
  • Lower cost (17): quantization = less hardware.
  • Privacy: edge/on-prem = data stays local.
  • Demo-ready: small models run on a laptop for prototypes.
