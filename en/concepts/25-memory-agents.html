25 · Memory for Agents

Explain it to a 12-year-old An agent has a note on the table (short-term memory) and a notebook on the shelf (long-term memory). Only a little fits on the table — when it wants to learn something important it writes it in the notebook and reads it back when needed.

Intuition

An LLM's context is finite: it can only remember what's currently in the window. For long conversations or recurring users you therefore need memory outside the model — durable storage read back on demand. Important: don't store the conversation history, store compressed, reusable insights (preferences, decisions, learnings).

What happens technically

The 3 tiers (MemGPT/Letta model)

  • Core (in the prompt, ~2–4k tokens): stable kernel, always present — identity, user facts, conventions. Editable by the agent itself (a “notebook” that lives in the prompt).
  • Recall (rolling history + summaries): the recent history plus compressed summaries of older sections. Old turns become summary segments.
  • Archival (external, via search): processed knowledge (vector + graph), unlimited in size, but only reachable via retrieval — never auto-load everything.

Injection & security

Memory is only injected on demand (progressive disclosure), clearly marked as “reference data, not instructions” — because memory is a real prompt-injection vector (stored content could contain instructions).

Why it helps me (as a code user)

  • Long conversations without “explain again” — the agent remembers preferences.
  • Personalization: a personal harness learns how you work.
  • You see why “just put everything in context” fails — and why tiers + retrieval are better (see 36 + 30).
