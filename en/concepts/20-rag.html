20 · RAG (Retrieval Augmented Generation)

Explain it to a 12-year-old The model can't know everything and forgets details fast. So before your question you tell it: "Here — first read these matching book pages," and only then: "Now answer the question using them." This way it answers with fresh, real information instead of guessing.

The three words

  • Retrieval — search for the text passages that match the question.
  • Augmented — attach those passages to the prompt (Concept 07).
  • Generation — the model answers based on them.

RAG in two phases: index once, then retrieve & generate per question.

How the search works (connection to Concept 02)

Documents are split into chunks and each is turned into an embedding (vector) — just like tokens in Concept 02. The question is embedded too. Cosine similarity between the question vector and document vectors finds the closest ones. That's the whole "search" — distance in space instead of keyword matching.

These embeddings + search live in a vector database (Chroma, pgvector, Pinecone, Qdrant). Offline: build the index. At runtime: retrieve only the top-k chunks and append them.

Why this is central for you as a code user

  • Your own data without retraining the model (10).
  • Freshness: documents change, model stays the same.
  • Fewer hallucinations: answers are tied to a source (with citation).
  • Standard building block: most "AI chatbots over your own data" are RAG.
