38 · Model Routing & Cascades

Explain it to a 12-year-old For “1+1” you don't need a supercomputer. Use the cheap tool for easy tasks and the expensive one only when it's really hard. That's model routing.

Intuition

Not every task needs the strongest (and most expensive) model. A router looks at the request and picks the right model: cheap/fast for routine (chat, extraction, summarization), strong for hard reasoning/coding tasks. That way you keep quality AND save cost.

What happens technically

1) Routing before generation

Two paths: (a) heuristics (image present? context size? keywords for task type) — deterministic, no extra call; (b) a small router LLM classifies the task (general/code/reasoning/private) in milliseconds.

2) Cascade (start cheap, escalate when needed)

Instead of guessing, start cheap and escalate: first a small model (L0), then on uncertainty/validation error/user rejection to the next level (L1, then L2). Important: max escalation levels + budget cap, otherwise costs explode.

3) Telemetry & feedback loop

Log every routing decision + result (cost, latency, error, success) → evaluate offline and improve the routing heuristic. Only switch online the improvements that won offline.

Why it helps me (as a code user)

  • Significantly lower cost at equal quality on hard tasks.
  • With local + cloud models: private/simple tasks local, hard ones to the cloud (see 27).
  • Fewer rate limits, because the small model handles most of the load.
