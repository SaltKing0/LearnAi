19 · Prompting Patterns

Explain it to a 12-year-old A prompt is how you talk the model into something. "Show me an example" (few-shot) helps it understand the pattern. "Think out loud step by step" (chain-of- thought) helps it with puzzles so it doesn't guess wrong right away. Both cost no training — just clever words.

Why prompting is the cheapest leverage

You learned in Concept 01: the model only guesses the next word. What you write before it (the prompt) controls which distribution it guesses from. Before you fine-tune a model (Concept 10) or build RAG (08): try a better prompt first. Often that's enough.

The most important patterns

Basic patterns

  • Zero-shot — just pose the task. The baseline.
  • Few-shot — 2–5 examples (input→desired output) in the prompt set the format and tone. Very strong for structure.
  • Chain-of-Thought (CoT) — "think step by step" / examples with intermediate steps. The model "writes along" what it does → better logic/math. Costs more tokens.

Advanced patterns

  • ReAct (Reasoning + Acting) — the model alternates between thinking and acting. "I need to know X → call tool Y → based on result → next step". The basis for agents.
  • Self-Consistency — ask the same question several times, take the most common answer. Reduces random errors.
  • Tree of Thought — explore several reasoning paths at once, pick the best. Like brainstorming for LLMs.
  • Prompt Chaining — split a complex task into several prompts; the output of prompt A is the input of prompt B.

Structure & control

  • System prompt vs. user prompt — system sets role/rules ("You are …", "Always answer as JSON"), user is the actual request.
  • Role prompting — "You are a senior developer with 10 years of experience" → changes answer quality.
  • Negative prompts — "Don't answer with...", "Avoid..." → excludes unwanted answers.
  • Structured output — "Give me JSON with fields x,y" → directly parseable in code.
