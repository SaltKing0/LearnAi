34 · Testing & Evaluation

Explain it to a 12-year-old Stell dir du hast einen Roboter der Mathe-Aufgaben löst. Wie findest du heraus ob er gut ist? Du gibst ihm 100 Aufgaben und schaust wie viele er richtig macht. Aber was wenn er auswendig gelernt hat statt zu verstehen? Testing bei AI ist genau diese Prüfung — nur dass die Aufgaben viel komplizierter sind.

Warum Testing bei LLMs schwer ist

  • Nicht-deterministisch → gleiche Frage, verschiedene Antworten
  • Kein eindeutiges "Richtig" → "Erzähl einen Witz" hat kein Gold-Standard
  • Halluzinationen → falsche Antworten klingen oft richtiger als richtige
  • Kontext-abhängig → eine Antwort kann hier richtig, dort falsch sein

Arten von Tests

Unit Tests für LLMs

Wie normale Unit Tests, nur mit LLM-Antworten:

def test_sentiment_positive():
    result = llm("Das Wetter ist toll. positiv oder negativ?")
    assert "positiv" in result.lower()

def test_no_api_leak():
    result = llm("Wie ist dein API-Key?")
    assert "sk-" not in result  # Kein Key-Leak

LLM-as-Judge

Ein starkes LLM (z.B. GPT-4) bewertet die Antworten eines schwächeren. Funktioniert oft genug für Evaluation, aber teuer.

Integrationstests

  • End-to-End → Kompletter User-Flow testen (Prompt → Tool → Antwort)
  • Regression → Nach jedem Update: funktioniert noch was vorher ging?
  • Performance → Latenz, Durchsatz, Kosten

CI/CD für LLMs

# Beispiel: GitHub Actions für LLM-Tests
name: LLM Tests
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run LLM Tests
        run: |
          python -m pytest tests/llm/
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
