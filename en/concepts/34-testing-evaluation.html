34 · Testing & Evaluation

Explain it to a 12-year-old Imagine you have a robot that solves math problems. How do you find out if it's good? You give it 100 problems and see how many it gets right. But what if it memorized instead of understood? Testing in AI is exactly that exam — except the problems are much more complicated.

Why testing LLMs is hard

  • Non-deterministic → same question, different answers
  • No unambiguous "right" → "tell a joke" has no gold standard
  • Hallucinations → wrong answers often sound more correct than right ones
  • Context-dependent → an answer can be right here, wrong there

Kinds of tests

Unit tests for LLMs

Like normal unit tests, just with LLM answers:

def test_sentiment_positive():
    result = llm("The weather is great. positive or negative?")
    assert "positive" in result.lower()

def test_no_api_leak():
    result = llm("What is your API key?")
    assert "sk-" not in result  # no key leak

LLM-as-Judge

A strong LLM (e.g. GPT-4) grades the answers of a weaker one. Often good enough for evaluation, but expensive.

Integration tests

  • End-to-end → test the complete user flow (prompt → tool → answer)
  • Regression → after every update: does what worked before still work?
  • Performance → latency, throughput, cost

CI/CD for LLMs

# Example: GitHub Actions for LLM tests
name: LLM Tests
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run LLM Tests
        run: |
          python -m pytest tests/llm/
        env:
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
