07 · Prompting-Patterns

Explain it to a 12-year-old Ein Prompt ist, wie du dem Modell zuredest. „Zeig mir ein Beispiel" (few-shot) hilft ihm, das Muster zu verstehen. „Denk laut Schritt für Schritt" (chain-of- thought) hilft ihm bei Knobelaufgaben, nicht gleich falsch zu raten. Beides kostet kein Training — nur geschickte Worte.

Why Prompting is the cheapest leverage

Du hast in Concept 01 gelernt: das Modell rät nur das nächste Wort. What du davor hinschreibst (der Prompt), steuert, aus welcher Verteilung es rät. Bevor du ein Modell feinjustierst (Concept 10) oder RAG baust (08): versuch es mit einem besseren Prompt. Oft reicht das.

The most important patterns

Basic patterns

  • Zero-shot — einfach die Aufgabe stellen. Basishaltung.
  • Few-shot — 2–5 Beispiele (Input→gewünschtes Output) im Prompt geben das Format und den Ton vor. Sehr stark bei Struktur.
  • Chain-of-Thought (CoT) — „Denk schrittweise" / Beispiele mit Zwischenschritten. Das Modell „schreibt laut mit", was es tut → bessere Logik/Mathe. Kostet mehr Tokens.

Advanced patterns

  • ReAct (Reasoning + Acting) — Modell alterniert zwischen Denken und Handeln. „Ich muss X wissen → rufe Tool Y → basierend auf Ergebnis → nächster Schritt". Basis für Agenten.
  • Self-Consistency — gleiche Frage mehrmals stellen, häufigste Antwort nehmen. Reduziert Zufallsfehler.
  • Tree of Thought — mehrere Denkpfade gleichzeitig explorieren, besten wählen. Wie Brainstorming für LLMs.
  • Prompt Chaining → komplexe Aufgabe in mehrere Prompts unterteilen, Output von Prompt A wird Input von Prompt B.

Structure & Control

  • System Prompt vs User Prompt — System setzt Rolle/Regeln („Du bist …", „Antworte immer als JSON"), User ist die eigentliche Anfrage.
  • Role Prompting — „Du bist ein Senior Developer mit 10 Jahren Erfahrung" → verändert Antwortqualität.
  • Negative Prompts — „Antworte nicht mit...", „Vermeide..." → exkludiert unerwünschte Antworten.
  • Structured Output — „Gib mir JSON mit Feldern x,y" → direkt parsebar in Code.
