17 · Cost & Latency

Explain it to a 12-year-old You pay for every word the model reads and writes — like postage stamps per sentence. And you wait until it has finished typing: the bigger the model and the longer the answer, the longer it takes.

What the cost consists of

  • Paid per token (02): input tokens + output tokens, often at different prices. A long system prompt (07/12) costs with every call.
  • Model size (04): bigger models more expensive per token, but often better. Trade-off: is a small 7B model enough (11/14)?
  • Self-hosting (06/14): instead of per token → per GPU hour. At high volume often cheaper.

Where the latency comes from

  • Autoregressive loop (01): each token is generated separately → answer length = number of steps. Hence streaming (12) feels faster.
  • Attention is quadratic (03/04): longer context → significantly more compute per token.
  • Batch/parallelism: API providers serve many requests at once → latency fluctuates under load.

Cost is linear in tokens; latency grows with answer length and (quadratically) with context.

Why this is central for you as a code user

  • Choose the model: not always the biggest — often a smaller one suffices for 1/20 of the cost.
  • Shorten prompts (07): fewer input tokens = less per call.
  • Caching: cache system prompts/reusable parts (with APIs).
  • Streaming (12): better UX at the same latency.
