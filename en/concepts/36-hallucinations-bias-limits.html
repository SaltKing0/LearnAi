36 · Hallucinations, Bias, Limits

Explain it to a 12-year-old The model sometimes "invents" things that aren't true — like someone who has to guess and pretends to know for sure. It doesn't do it out of malice, but because it only guesses the next word (Concept 01) and doesn't "know" what is true.

Hallucinations

Because the model knows nothing, it only guesses probabilities (Concept 01), a wrong answer sounds just as confident as a real one. There is no internal "true/false" filter — it optimizes for "plausibly continuing text". Especially with rare facts or missing context.

  • Architectural cause: attention (03) only mixes context, trained on "what often follows" (05) — not on "what is true".
  • Countermeasures: RAG (08) brings in sources; eval (15) catches errors; forcing "I don't know" via prompt (07).

Hallucinations arise because the model guesses instead of knows — and can be contained with three levers.

Bias (distortion)

Models learn from human texts (05) — including their prejudices, stereotypes, imbalances. The model mirrors the training dataset. Awareness + countermeasures (diversity in data, RLHF/DPO from 10) needed.

Hard limits

  • No real knowledge/counting/logic at the core — it guesses patterns.
  • Context length is limited (02/04) — too long text "falls out".
  • No access to the world without tools (09) — no live data.
  • No consciousness — "thinking" is weighted information mixing.

Demo: source vs. no source

Simulation: without a source the model "invents" a study; with RAG (08) it names the source and is more cautious.

Why this is central for you as a code user

  • Never trust blindly: for facts use RAG + citations (08), for critical outputs eval/human review (15).
  • Prompting (07): "If unsure, say so" reduces hallucination.
  • Compliance/risk: bias in products is a real problem.
