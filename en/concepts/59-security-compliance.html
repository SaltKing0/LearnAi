59 · Security & Compliance

Explain it to a 12-year-old Security is locking the doors: making sure only the right people get in (authentication), only do what they're allowed (authorization), and that messages can't be read or faked along the way (encryption). For AI, there's an extra door to watch — the model itself can be tricked into doing things it shouldn't (prompt injection).

Intuition

Security is a threat model: you ask "who might attack this, and how?" then design defenses. For a normal web app the big risks are injection, broken access control, and data leaks. For an AI app, add prompt injection and data exposure through the model. Compliance (GDPR, SOC 2, etc.) is the legal/audit side — proving you handle data responsibly.

Application security (AppSec)

OWASP Top 10 is the standard list of web-app risks. The ones you'll meet most:

RiskWhat it isDefense
SQL injectionAttacker injects SQL into your queryParameterized queries / ORMs (never string-concat)
XSSAttacker injects script into a page others viewEscape output, sanitize, CSP headers
Broken access controlUsers reach data they shouldn'tAuthN + AuthZ on every request, least privilege
Security misconfigDefault creds, exposed debug, open portsHardening, secrets management, scanning

Rule: never trust input. Sanitize/validate everything that crosses a trust boundary.

Authentication & authorization

  • Authentication (who are you?) vs. Authorization (what may you do?).
  • OAuth 2.0: delegated authorization — lets an app access your data without your password (e.g. "Sign in with Google").
  • OpenID Connect (OIDC): identity layer on top of OAuth 2.0 — gives you the who.
  • JWT: signed token carrying claims (who + what they can do) — stateless auth, but must be validated carefully (signature, expiry, audience).
  • RBAC / ABAC: Role-Based (permissions by role) vs. Attribute-Based (permissions by attributes/context) access control.

Cryptography

  • Encryption at rest (data stored — AES) and in transit (data moving — TLS/HTTPS).
  • Hashing: one-way (passwords, integrity) — SHA-256; never store plaintext passwords, use salted hashes (bcrypt/argon2).
  • PKI / certificates: public-key infrastructure — how TLS establishes trust via certificate authorities (that's the "lock" in your browser).
  • Key management: keys are the crown jewels — use a key vault (AWS KMS, etc.), rotate them, never hardcode secrets.

Why this helps me (as an AI/code user)

  • Prompt injection is the AppSec of LLMs — untrusted input steering the model (26).
  • API keys & secrets: never ship keys in code; use env vars / vaults — the same key-management discipline (12).
  • Sandboxing: running model-generated code or tools needs isolation (40).
  • Data protection: what you send to a model may leave your control — a compliance decision (14).
