18 · Deployment

Explain it to a 12-year-old Ein Modell auf dem Schreibtisch nützt niemandem. „Deployment“ heißt: es so aufstellen, dass andere es benutzen können — als Dienst im Internet, oder sogar auf dem Handy. Und „Quantisierung“ ist das Diät-Machen: das Modell schrumpfen, damit es auf schwächerer Hardware läuft.

Drei Wege, ein Modell bereitzustellen

  • API / Cloud (Inference-Server) — du startest z.B. vLLM/ Ollama und rufst es wie in Concept 12 auf, nur selbst gehostet (aus 06/14). Skaliert, aber braucht Server/GPU.
  • Edge / Lokal — Modell läuft auf dem eigenen Rechner/ Handy/im Browser (WebGPU, llama.cpp). Privat, offline, aber begrenzte Power.
  • Embedded / On-Premise — in deiner Firma, keine Daten verlassen das Haus (14).

Drei Deployment-Wege; Quantisierung macht besonders Edge/On-Premise erst möglich.

Quantisierung (Verbindung zu 04/17)

Modelle speichern Gewichte als 16-Bit-Floats. Quantisierung reduziert sie auf 8/4 Bit — das Modell wird ~4× kleiner und schneller, oft mit kaum sichtbarem Qualitätsverlust (04). Das ist, warum ein 7B-Modell plötzlich auf dem Laptop läuft. Kostet weniger RAM, weniger Latenz (17), keine GPU nötig.

Warum das für dich als Code-Nutzer zentral ist

  • Self-Hosting (14): eigene API ohne Dritte, Kontrolle.
  • Kosten senken (17): Quantisierung = weniger Hardware.
  • Privatsphäre: Edge/On-Prem = Daten bleiben lokal.
  • Demo-tauglich: kleine Modelle laufen auf dem Laptop für Prototypen.
