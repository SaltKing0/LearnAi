08 · RAG (Retrieval Augmented Generation)

Explain it to a 12-year-old Imagine you're taking a test and you're allowed to look things up in your textbook. RAG is like that — the model doesn't need to know everything by heart. It can "look up" relevant information before answering. This way, it can answer questions about things it was never trained on.

What is RAG?

RAG = Retrieval Augmented Generation. Instead of relying only on what the model learned during training, RAG retrieves relevant documents at query time and includes them in the prompt.

Why RAG?

  • Up-to-date info → Model knowledge has a cutoff date
  • Domain knowledge → Your company docs, private data
  • Hallucination reduction → Ground answers in real documents
  • Source attribution → Show where the answer came from

The RAG Pipeline

  1. Index → Split documents into chunks, embed them, store in vector DB
  2. Retrieve → User query → embed → find similar chunks
  3. Augment → Insert retrieved chunks into prompt
  4. Generate → Model answers based on retrieved context

Why this matters to you

  • Chat with your data → Build a bot that knows your docs
  • Cost-effective → Cheaper than fine-tuning for most use cases
  • Fast iteration → Add new docs without retraining
