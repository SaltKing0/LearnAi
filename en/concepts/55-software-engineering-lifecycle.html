55 · Software Engineering & Lifecycle

Explain it to a 12-year-old Writing code is the fun part, but a real project is a team sport with rules. You plan in short rounds (Agile), save every version so you can go back (Git), have teammates check your work before it's merged (code review), and test so you don't break what already worked. This page is about the process around the code.

Intuition

Software spends most of its life being changed, not written. So the discipline that matters is making change safe and reversible: small increments, version control, automated tests, and review. This is true whether you're building a CRUD app or an AI agent harness — the practices are the same.

Version control & collaboration

  • Git: snapshots (commits) of your whole project; branch = a separate line of work; merge = combine lines.
  • Branching strategies: Gitflow (long-lived develop + feature/release/hotfix branches — good for releases); trunk-based (everyone commits to main in small PRs, feature flags — good for CI/CD velocity).
  • Code review + pull requests: the change lives on a branch, a human (or AI) reviews the diff, CI runs checks, then it merges. Review is a quality gate and a knowledge-sharing tool.

Testing & quality

LevelWhat it checksMental image
UnitOne function in isolationTest the calculator's add()

Performance / loadSpeed & behavior under stress1000 users at once — does it survive?

Automated testing frameworks (Jest, pytest, Playwright, etc.) run these on every change, usually in CI. For AI specifically, "testing" extends to evals and LLM-as-judge — see 34.

Why this helps me (as an AI/code user)

  • Eval-driven development: treating model behavior like tests (write the expected answer first) is TDD applied to AI (34).
  • Agent harnesses are software: they need version control, review, and tests like anything else — the "agent loop" is just code.
  • PR workflow: the git/review/CI loop is exactly how you'll collaborate on real AI projects.
  • Prompt as code: prompts, configs, and evals belong in version control, reviewed like code.
