32 · Open-Source vs. Closed Models

Explain it to a 12-year-old Some models are like a recipe book anyone can buy and cook from (open). Others are like a restaurant: you get the food (the answer), but the recipe stays secret and you pay per plate (closed/API).

The two worlds

  • Open-source (Llama, Mistral, Qwen, …): weights + code are public. You can run them locally, adapt them (10), host them yourself.
  • Closed / proprietary (GPT-4o, Claude, Gemini): only reachable via API (12). The model itself stays with the company.

Demo: flipping pros/cons

What matters in practice

  • Cost: open locally = hardware once, then (almost) free; closed = ongoing per-token cost.
  • Data privacy: open can be on-premise (no data leaves your house); closed sends prompts to third parties.
  • Control: open = you decide version, quantization, fine-tuning; closed = the company changes the model whenever it wants.
  • Peak performance: closed frontier models are often stronger than the best open ones — relevant for hard tasks.

Why this is central for you as a code user

  • Strategy: prototype with open (free, private) → if needed use closed for quality.
  • Learning: open models are studiable (weights, code).
  • Self-hosting (Stage F) requires open.
