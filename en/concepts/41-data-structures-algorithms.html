41 · Data Structures & Algorithms

Explain it to a 12-year-old A data structure is how you arrange your stuff — books in a pile, or sorted on a shelf, or in labeled boxes. An algorithm is the recipe of steps you use to find or rearrange it. Some arrangements make "find the red book" instant, others make it take forever. Choosing the right arrangement is half of programming.

Intuition

Almost every program is really two questions: how do I store the data (data structure) and how do I process it (algorithm). The trick is that no structure is best at everything — a hash map finds things in ~O(1) but can't keep order; a sorted array keeps order but inserts are slow. You trade one thing for another, and Big O notation is the ruler you use to measure the trade.

Algorithms — the recipes

  • Sorting: Bubble (O(n²), simple), Merge (O(n log n), stable), Quick (O(n log n) avg, fast in practice).
  • Searching: Linear (O(n), any list), Binary (O(log n), only on a sorted list — halving each step).
  • Graph traversal: BFS (level by level, shortest path in unweighted graphs), DFS (depth first, good for exploring/cycles).

Big O — the ruler

Big O describes how runtime grows as the input grows, ignoring constants. It answers "what happens at 10× the data?"

NotationNameFeelExample
O(1)ConstantInstant, alwaysHash lookup, arr[i]
O(log n)LogarithmicDoubling data barely mattersBinary search, balanced tree
O(n)LinearScales 1:1Scanning a list
O(n log n)LinearithmicGood sortingMerge/Quick sort
O(n²)QuadraticDoubling data = 4× workNested loops, bubble sort
O(2ⁿ) / O(n!)Exponential / factorialDies fastBrute-force subset / permutation

Rule of thumb: O(n²) is the danger line. n=1000 → a million operations; n=100,000 → ten billion. That's why you see "O(n²)" everywhere in AI — attention is quadratic in the sequence length, which is exactly why long contexts are expensive (see 17).

Why this helps me (as an AI/code user)

  • Embeddings & vector search: "find the nearest embedding" is a search problem — brute-force is O(n·d), which is why ANN indexes (HNSW, etc.) exist (30).
  • Attention is O(n²): the transformer's core cost is a complexity fact, not a bug. Understanding Big O tells you why context windows get expensive.
  • KV cache, token buffers, queues in agent harnesses are all data-structure choices — knowing the trade-offs helps you pick the right one.
  • Reading model code: tokenizers, beam search, sampling loops are algorithms; recognizing the pattern makes them readable.
