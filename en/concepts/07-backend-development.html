07 · Backend Development

Explain it to a 12-year-old The backend is the kitchen of a restaurant: the frontend is the menu and the waiter, but the real work — fetching the data, doing the math, talking to the database — happens in the kitchen. Your phone just sends a "give me this" request, and the kitchen answers with the finished dish.

Intuition

The backend is where the logic, data, and integrations live. Its job: receive requests, enforce rules, read/write data, and return responses — reliably and at scale. For AI, the backend is where you call the model, build RAG pipelines, and manage vector databases.

API development

StyleIdeaBest for
RESTResources + HTTP verbs (GET/POST/PUT/DELETE), JSONSimple, widely compatible CRUD APIs
GraphQLOne endpoint; client asks for exactly the fields it needsFlexible queries, many clients, mobile
gRPCTyped, binary, high-performance RPC (protobuf)Internal service-to-service, low latency
WebSocketsPersistent two-way connectionReal-time: chat, streaming, live updates

OpenAPI / Swagger is a machine-readable spec of your REST API — auto-generates docs, clients, and tests. LLM APIs (OpenAI-compatible) are themselves REST with an OpenAPI-style schema, and tool-calling reuses that contract (29).

Server frameworks

  • Node.js: Express (minimal) and NestJS (structured, TypeScript) — the agent-framework home turf.
  • Python: FastAPI (modern, typed, async — very popular for LLM backends) and Django (batteries-included).
  • Java: Spring Boot — heavyweight enterprise standard.
  • Go: high-concurrency, simple, fast — great for proxy/serving layers.
  • .NET: ASP.NET Core — enterprise C# stack.

Databases & storage

Relational (SQL): PostgreSQL, MySQL. Data in tables with rows and relationships. Key ideas: normalization (removing duplicate data by splitting tables), indexing (speeding up lookups at the cost of writes), ORMs (object-relational mappers — SQLAlchemy, Prisma, Hibernate — let you use tables like objects).

Non-relational (NoSQL): chosen when the data shape doesn't fit rigid tables or you need scale/performance:

TypeModelExampleUse for
DocumentJSON-like documentsMongoDBFlexible schemas, content
Key-valueSimple key→value, super fastRedisCaching, sessions, rate limits
Wide-columnColumns grouped, huge scaleCassandraMassive write throughput
GraphNodes + edgesNeo4jRelationships, knowledge graphs
VectorEmbedding similaritypgvector, Qdrant, MilvusRAG, semantic search (30)

Why this helps me (as an AI/code user)

  • LLM backends: FastAPI/Node services that proxy model calls, stream tokens, and handle auth are backend work (12).
  • RAG: retrieval needs a vector database + an embedding pipeline — a classic backend architecture (8, 30).
  • Tool-calling: tools are just APIs with an OpenAPI-style contract the model calls (29).
  • State & caching: Redis for KV-cache/rate-limits, SQL for conversation history — the same backend patterns apply to agents.
