48 · DevOps, Infrastructure & Cloud

Explain it to a 12-year-old DevOps is making sure your app gets from your laptop to the real world safely and automatically. Instead of "works on my machine," you package it in a box (Docker), run the checks automatically (CI), ship it (CD), and keep an eye on it (monitoring). The cloud is just renting someone else's huge computer instead of buying your own.

Intuition

Software only matters when it runs reliably in production. DevOps is the set of practices that automate the journey from code to running service and back: package it, test it, ship it, watch it. For AI this is doubly important — models are heavy, GPUs are scarce, and inference must stay up and observable.

Containerization & orchestration

  • Docker: packages your app + its exact environment into a container image — "it runs the same everywhere." The de-facto standard.
  • Podman: a Docker-compatible, daemon-less alternative (more secure defaults, rootless).
  • Kubernetes (K8s): orchestrates many containers across many machines — scaling, restarts, load balancing, rolling deploys. Powerful but complex.

CI/CD pipelines

flowchart LR C["Commit / PR"] --> CI["CI: build + lint + unit tests + evals"] CI --> CD["CD: build image, deploy"] CD --> P["Production"] P --> M["Monitor: logs, metrics, alerts"] M -->|"feedback"| C

The CI/CD loop — automated checks before deploy, monitoring after. For AI, "tests" include evals on model output.

  • GitHub Actions / GitLab CI: define pipelines in YAML inside the repo; runs on every push/PR.
  • Jenkins: older, self-hosted, very flexible.
  • Automated build → test → deploy workflows make releases safe and frequent.

Cloud & Infrastructure as Code (IaC)

  • Cloud providers: AWS, Google Cloud, Azure — rent compute, storage, GPUs, managed services.
  • IaC: define infrastructure in code, not by clicking. Terraform (provider-agnostic) and CloudFormation (AWS-native) let you version and review your whole infra like code.
  • GPU-specific: for AI you often need GPU instances or serverless GPU — the same cloud patterns apply, just pricier (17).

Observability

  • Logging: structured event records (what happened).
  • Metrics: numeric counters/gauges (requests/sec, latency, error rate).
  • Distributed tracing: follow one request across many services (OpenTelemetry is the standard).
  • Tools: Prometheus + Grafana (open-source metrics + dashboards), Datadog (SaaS), OpenTelemetry (the collection standard).

Why this helps me (as an AI/code user)

  • Deploying models: vLLM/TGI as containers, orchestrated with Docker/K8s, behind a serving layer (33).
  • Eval in CI: run evals and LLM-as-judge automatically on every change (34).
  • Cost control: autoscaling and right-sizing GPU instances are DevOps decisions that hit the budget (17).
  • Observability of agents: tracing an agent loop across model + tools is distributed tracing in miniature.
