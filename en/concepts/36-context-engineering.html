36 · Context Engineering

Explain it to a 12-year-old Think of a backpack: you can't carry everything at once. While packing you decide what matters, and you put the unimportant stuff away so there's room for what matters. That's context engineering for LLMs.

Intuition

The context (everything you hand the model) is a finite and expensive resource. Every token in the prompt is reprocessed at every step — more context means more cost and (often) worse answers, because the model gets “distracted.” Context engineering means choosing the smallest set of high-signal tokens that maximizes the desired behavior.

Especially with agents the problem explodes: each loop step re-sends the whole history → the context grows quadratically over time (the O(n²) problem). That's why context management is the biggest cost lever of a harness.

What happens technically

1) Prompt caching (cache shape)

Anthropic/OpenAI cache a byte-stable prefix (system prompt + tool schemas + prior conversation). If you put the stable part first and the volatile part (clock, file listing, plan status) at the end and never change the order, almost all tokens are read from cache → one turn costs a fraction (often 1/10).

2) Compaction instead of endless growth

Instead of hitting an emergency at 90% context, compress early (e.g. at 70/80/85%): old tool results are replaced by short reference pointers, and a summary takes over. Important: don't compress every turn (it destroys caching) — compress at natural phases.

3) Progressive disclosure

Only name + description of all tools/skills in the prompt (~30–50 tokens each), load the full content only when needed. A 200-token index + on-demand retrieval beats a 5000-token pre-loaded block.

Why it helps me (as a code user)

  • Cost: In long agent runs, context management is the biggest saving lever.
  • Quality: Too much context degrades answers (the model “loses the plot”) — less, but targeted, is better.
  • Small models: With a limited window every token counts — discipline is a must.
